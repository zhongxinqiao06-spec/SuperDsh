# Web Admin 开发规范

本规范适用于 `apps/web-admin` 的新实现及其配套根脚本、检查和部署接线。实施须同时遵循[基础计划](../../docs/plans/web-admin-01-foundation.md)、[功能计划](../../docs/plans/web-admin-02-function-and-interaction.md)和[验证计划](../../docs/plans/web-admin-03-parity-validation.md)。实际进度以计划勾选和验证记录为准，不得把文档写入当作开发完成。

## 产品边界

- 保持现有 `apps/admin` 源码、已有工作区修改、启动入口及显式 `compose.legacy.yml` 部署。根 Compose 默认启动 Vue 和 FastAPI。新应用不导入、代理到或启动旧管理端业务实现，不依赖退休后端。
- 前端固定为 `fronted`，使用 Vue3 + TypeScript；平台业务后端固定为 `backend`，使用 Python FastAPI。DSH、桌面和 Android 的既有协议及身份边界保持兼容。
- `backend/app` 只容纳 Python 后端源码，不放 `.mjs`、`.js` 或 TypeScript 桥接。固定 DSH 确需的引擎侧插件注册放独立 `engine-adapter/src`，使用 TypeScript；工具业务逻辑仍在 Python。引擎适配编译输出放 `engine-adapter/dist`，不提交、不混入源码；运行时不临时编译。仓库装配与构建脚本使用 TypeScript；后端原生 Python 启动统一由 `backend/main.py` 承担，命令为 `uv run python main.py`，保留配置加载、迁移和热重载，不复制 ASGI 业务装配。
- 平台提供通用资源、配置、权限、版本、会话绑定、执行收据、确认、证据与成果能力。Office 等场景通过可配置工具、技能和智能体组合接入，不在核心按助手名称写分支。
- DSH 是唯一 Agent 执行引擎。LangGraph 仅为可选的业务状态或工具步骤实现，不增加第二个 Agent loop、调度队列或强制图编辑器。

## 版本来源与无版本路由

- 发布版本只有一份权威项目元数据，构建时生成前端与后端只读构建信息。页面、业务服务、错误消息、Docker 启动脚本不得重复填写版本号，不以运行目录名称推断版本。
- DSH 和第三方依赖版本从现有来源清单、包 manifest 与锁文件读取，部署镜像版本由统一部署配置传入。保持固定版本和完整性校验，不把“去硬编码”实现为 `latest`、浮动安装或运行时下载。
- 外部协议必需的 `schemaVersion`、握手标识和生成 codec 由契约元数据定义；不可因本规范删除字段或改变线上协议。不可变数据库迁移 revision 属于迁移记录，不在业务代码复制。
- 技能、工具、配置和会话绑定的 revision/version 是持久业务数据，按记录读取、比较和冻结，不能替换成全局发布版本或硬编码常量。
- 新规范 HTTP 路径使用 `/api` 下的资源路径，WebSocket 使用统一规划的无版本路径。页面路由、资源名、路由模块和 DTO 名称不新增 `v1/v2`、`-v2`、`_v2` 等版本后缀，也不按版本复制业务实现。
- 无版本路由规则针对新产品自己的入口；第三方供应商的版本路径、DSH/MCP 协议标识及外部 OAuth 回调属于外部契约，不做批量改写。旧包和生成协议不为满足扫描规则移动或改名。
- 前端请求统一经过 API 客户端和集中 base URL 配置；模块声明相对资源路径，组件与 composable 不自行拼接版本前缀。WebSocket、下载和资源 URL 同样集中构造。
- 旧客户端的 `/api/v2` 及带版本的历史资源路径只在 `deployment/compatibility-routes.json` 中集中声明入口映射，保留作为兼容别名；新前端只调用无版本规范入口。该文件是兼容映射唯一来源，不在各模块维护另一份旧路由。
- 映射按 HTTP 方法、路径模板、传输类型和参数规则精确声明，指向同一无版本业务 handler。开发直连 Python 和生产反代均据此工作；启动检查冲突、遗漏和歧义。不得用全局字符串替换、POST/WS 重定向或重复业务 handler 实现兼容。
- 兼容入口保留查询与路径编码、签名、票据作用域、WebSocket Upgrade/子协议/帧/关闭行为。原入口上下文只能由可信内部适配器建立，不相信浏览器伪造的兼容模式请求头。
- Cookie Path、登出清理、Location、公开下载链接与 OAuth 跳转须显式验证新旧入口。原刷新及 OAuth 状态 Cookie 的历史路径从兼容配置派生，不在业务路由写字面量；OAuth 外部客户端身份、签名 URI 和已注册回调不得盲目改写。

## 按领域和职责拆分代码

目录按明确职责与稳定业务能力组织。前端采用若依 Vue3 风格的职责目录，再按领域归档；后端保持领域内严格分层。一个文件承担清晰职责；相关方法可以内聚，不要求每个函数一个文件，也不为了层数建立空目录或无意义转发类。

前端统一位于 `fronted/src`，按若依 Vue3 风格划分；不再并存 `app`、`features` 两套目录：

| 目录                   | 职责                                                             | 禁止承担的职责                         |
| ---------------------- | ---------------------------------------------------------------- | -------------------------------------- |
| `views/<domain>`       | 页面装配、加载和权限状态，页面专属组件放其 `components`          | 大段业务算法、直接 HTTP、复杂事件归并  |
| `components`           | 跨页面通用 UI、明确 props/emits 和展示状态                       | 持久化、全局流程、直接修改其他模块状态 |
| `composables/<domain>` | 响应式用例、订阅和页面生命周期协作，通用方法直接放 `composables` | 无边界的万能服务或跨领域共享仓库       |
| `api/<domain>`         | 请求 DTO、端点调用与返回值适配                                   | 页面状态、交互副作用、硬编码 URL 版本  |
| `store/modules`        | 有明确所有者和生命周期的共享状态                                 | 混存跨账号数据、所有业务逻辑和所有 API |
| `types/<domain>`       | 公共类型、模块输入输出契约                                       | 执行代码、隐含初始化                   |
| `utils/<domain>`       | 本领域无状态、可独立测试的纯方法                                 | 网络、数据库、全局状态、完整业务流程   |
| `router`、`layout`     | 路由装配与公共布局                                               | 领域规则、请求实现、跨账号业务状态     |
| `assets/styles`        | 主题变量与页面样式                                               | 运行配置、组件业务逻辑                 |

- 应用入口为 `src/main.ts` 与 `src/App.vue`，路由入口为 `router/index.ts`。认证会话协调放 `store/session-controller.ts`，共享状态放 `store/modules`；基础请求、地址配置、错误适配分别放 `utils/request.ts`、`utils/api-config.ts`、`utils/errors.ts`，构建信息放 `utils/build-info.ts`。这些基础适配不承载领域流程，其他 `utils/<domain>` 保持纯方法。
- 页面、API、composable、类型和纯方法使用一致领域名称，避免同一能力散落多个命名体系。只为已有职责建立目录，不增加空目录、转发文件或无意义的 `index.ts`；禁止形成万能 `utils.ts`、超大页面或全能 store。
- 组件通过 props/emits 或明确公共接口协作，业务方法与组件展示分开；订阅、计时器、对象 URL 和请求取消必须有生命周期清理。
- Vue 组件使用 PascalCase，普通前端模块使用 kebab-case。公开接口具有明确 TS 类型，不使用 blanket `any`、`ts-nocheck` 或宽泛类型断言绕过设计问题。
- 若依约束的是目录与职责分层，产品保留旧管理端的品牌基调，视觉与交互按已确认的[公共组件统一方案](../../docs/plans/web-admin-ui-unification.md)调整。颜色、字体、间距和圆角集中在 `assets/styles/tokens.css`，全局排版在 `base.css`，Element Plus 外观适配在 `element.css`；布局、管理页、工作台分别维护领域样式。新增控件必须继承主题语义，禁止恢复组件库默认蓝色或在各页面复制另一套全局皮肤。图标统一使用 `components/base/AppIcon.vue`，保留静态资源来源和许可。
- 跨页面 UI 按 `components/layout`、`management`、`overlay`、`form`、`feedback`、`settings`、`base` 归档。页面局部样式只处理领域结构，控件复用公共样式。
- 主列表依次展示页面名称、工具栏、列表与底部分页。PageHeader 只呈现页面名称。FilterBar 将搜索、筛选与新增、导入、刷新等页面动作相邻排列。空数据引导、权限、校验与错误放在相关操作附近。设置页在对应设置项旁提供编辑。
- RowActions 在记录上直接展示当前角色可用的全部管理动作。按实际按钮数量分配桌面操作列，窄屏优先复用卡片并允许按钮换行。危险操作显式确认，提交期间阻止重复操作。工作台侧栏的历史会话使用行右侧的省略号菜单。菜单支持鼠标、键盘与触屏，打开时保留当前会话。项目操作放在项目名称下方。
- 主列表用 ManagementList 独立滚动。ManagementPagination 在主内容区底部左侧显示总数与范围，右侧提供每页条数和翻页，翻页后列表回顶。弹窗、设置卡片与嵌套列表各自管理分页。长表单固定标题与底栏，正文滚动，分区共享草稿，校验定位到字段，保存失败保留输入。

后端采用用户确认的 RuoYi-FastAPI 风格，模块位于 `backend/app/modules/<domain>`，调用方向严格为 `controller → service → dao`：

| 层           | 职责                                 | 依赖边界                                                 |
| ------------ | ------------------------------------ | -------------------------------------------------------- |
| `controller` | 路由、协议转换、依赖注入与授权入口   | 只调用 service，不直接访问 dao、ORM 或进程               |
| `service`    | 业务校验、资源授权、用例、事务和幂等 | 调用本模块 dao 或其他模块公开 service，不依赖 controller |
| `dao`        | 查询、条件更新和持久化               | 操作本模块 DO，不写 HTTP、权限决策、跨领域流程或提交事务 |
| `entity/do`  | SQLAlchemy 数据库映射与结构          | 不承担业务编排，不直接用作 HTTP 返回模型                 |
| `entity/vo`  | Pydantic 请求、响应、分页与校验模型  | 不执行 SQL、网络或业务副作用                             |

纯业务值对象按实际需要放 `entity/bo`，外部能力端口放 `service`；数据库会话可由装配注入，事务提交与回滚始终由 service 管理。目录及文件沿用 `user_controller.py`、`user_service.py`、`user_dao.py` 等清晰命名，不再并存另一套 `api/application/domain/infrastructure` 领域分层。

- 跨模块用公开 service 接口或显式事件协作，禁止跨领域直接写表、循环 import 和直接依赖另一个模块的 dao、DO 或内部实现。
- 通用数据库连接、配置、日志和存储客户端位于 `backend/app/infrastructure`；DSH 协议位于 `integrations/dsh`；工具实现位于 `backend/toolkits`；这些实现通过端口接入用例。
- 每个用例有明确输入、输出、授权、事务和失败语义。业务规则抽成方法或领域对象，不能堆在路由、构造函数、模块导入副作用或巨大 service 类中。
- Python 模块及函数使用可导入的 snake_case、类使用 PascalCase；提供类型注解，Ruff 与类型检查落实格式和契约。不要为了模仿 Java 机械增加 interface/impl 空层。
- 模块的规模与依赖复杂度触发拆分审查；禁止仅按文件行数切碎代码，或以低于行数阈值代替职责检查。

## 中文注释与契约说明

- 自有公开模块、导出方法/类、业务用例、组件和 composable 的公共契约使用中文注释或 docstring，说明职责、关键输入输出和限制；必要时说明副作用及异常语义。
- 并发控制、权限边界、幂等、重试、状态迁移、取消、恢复、兼容映射和非直观算法必须有中文说明，解释原因与不变量。
- 普通私有辅助函数不逐行翻译代码。注释保持简洁、准确并与实现同步；不使用占位说明、复制失效注释或以注释代替输入校验。
- 标识符、协议字段、库名和日志稳定事件码使用既有命名，不把它们翻译成中文。第三方、生成代码与不可变协议文件不为中文注释手工改写，说明写在自有适配层或生成器中。
- 审查注释的内容质量，不用中文字符数或注释覆盖率作为唯一通过条件。

## 测试与过程文件统一隔离

所有新测试源文件、测试脚本、fixture、mock、种子、基准清单和黄金样本位于 `apps/web-admin/tests`，按职责划分：

```text
tests/
  fronted/          # 前端方法、组件和状态测试
  backend/          # 领域、用例、仓储和接口测试
  contracts/        # HTTP、WS、扩展及跨语言契约测试
  integration/      # 数据库、存储、真实 DSH 等集成测试
  e2e/              # 浏览器端到端测试
  parity/           # 版本对照、features 清单与基准索引
  fixtures/         # 脱敏或合成的可复用输入、mock、种子和黄金样本
  tooling/          # 命令、部署、架构检查及基准导出等测试工具
```

- `fronted/src`、`backend/app`、`backend/toolkits`、生产 `resources/contracts/scripts` 不放测试代码、`__tests__`、mock、报告或试验文件；不再新建 `fronted/tests`、`backend/tests`。生产 Schema 留在 `contracts`，测试用契约快照和旧源码基线清单放 `tests`；运行旧应用的临时源码副本放独立验证目录。
- 截图、trace、日志、coverage、JUnit/HTML 报告、数据库快照、临时下载、测试 Home/workspace、缓存和 `.pyc` 等过程产物统一输出到 `<repo>/.superdsh-work/web-admin-validation/<run-id>`；路径由测试入口计算并传入，不能依赖偶然 cwd。
- 需要入库的黄金样本和脱敏 fixture 必须经过明确审查并放 `tests`；不能把一次运行的整套输出自动升级成基准。生产默认技能/示例是产品资源，不与测试种子混用。
- 配置 pytest、前端测试器、浏览器、覆盖率及 Python 缓存路径，禁止工具默认在业务目录写测试产物。对应临时目录被 Git 忽略，不上传密钥或真实用户数据。
- 生产业务不得 import 测试目录；生产类型检查配置、构建、Python 打包和 Docker 运行镜像排除测试与过程文件。测试使用独立配置接受类型检查，不因目录隔离而免检。CI 的独立 test 阶段可以使用测试源，最终 runtime 阶段不能携带它们。
- 构建和启动脚本仍位于生产工程脚本目录；测试 runner、诊断复现及差分导出脚本位于 `tests/tooling`，根命令只作调用接线。

## 健壮性要求

- 首个管理员由后端启动用例按持久配置创建，默认值集中在配置资源；前端不包含初始密码或初始化令牌表单。仅在空库内以事务锁执行，重复启动不覆盖已有账号、密码、角色或禁用状态，非法配置不得静默回退。
- 默认模型由后端模型 service 在启动时读取 `backend/config/model-defaults.json`；连接、能力及默认选择原子同步且幂等，密钥加密存储。配置只管理明确声明的记录，不接管个人模型；不依赖旧平台文件或测试导入脚本。真实配置按用户要求放在后端 config，排除 Git 和 Docker 构建上下文，Docker 只读挂载；仅提交无凭据模板。测试必须显式覆盖独立合成配置，不能读取该真实文件。
- 本地开发启动先实际执行 Python 检查虚拟环境，再按锁文件同步依赖并验证模块导入；不以 `python.exe` 文件存在代表环境可用。缺失或损坏时自动准备，失败不继续迁移和启动；环境准备与应用／引擎构建分开，预览不得隐式执行 build。
- 输入在边界校验类型、大小、格式、路径、资源归属和配置 Schema；服务端授权覆盖 HTTP、WS、后台恢复与下载，不依赖前端按钮状态。
- 业务异常有稳定错误语义，未知异常记录可关联的脱敏日志并返回适当失败；不吞异常、不返回伪成功、不暴露凭据、堆栈或服务器路径。
- 外部请求、数据库连接、锁等待和受管进程设明确超时与取消传播；执行结束、错误、取消和关闭均释放连接、文件、锁和进程。等待用户确认与实际执行超时分开计算。
- 只对明确安全、幂等的暂时失败执行有上限的退避重试；有副作用的调用先记录稳定操作 ID 和收据。结果未知先核对，不生成新 ID 自动重发收费或执行请求。
- 并发修改使用事务、版本条件或锁保证一致性；事务保持短小，不持有事务等待用户或长期网络。重复请求、迟到结果、租约失效和重启均有明确行为。
- DSH 启动前持有运行所有权，Host 和 Connector 都就绪才报告可用；退出及租约失效先撤销执行能力并回收所属进程。仅在确认原执行者退出或被有效隔离后才允许新执行者接管，不用换锁名绕过重复启动保护。
- 流式事件使用有界缓冲和背压，验证序列、去重与恢复；关键状态落库后再确认，不悄悄丢事件或跳过失败阶段。
- 账号切换、权限撤销、页面卸载和异步完成存在代际检查；旧请求不能污染新账号或覆盖新草稿、修订与成果。
- 日志关联 request/session/run/call 等稳定标识，按等级记录，凭据脱敏；存活、就绪与具体依赖故障分开表达，不能用首页成功掩盖执行失败。
- 工具安装、模型配置、索引和业务状态失败时保留有效旧状态或明确回滚；不自动换供应商、降级权限、丢弃数据或修改用户配置。
- 测试必须覆盖本模块适用的边界、负向、并发、超时、取消、重启和依赖失败。真实引擎、受控模型、外部模型与真实设备的证据分开记录。

## 开发与交付门槛

- Python 启动在读取业务配置、迁移和导入第三方模块前设置外置字节码缓存，热重载和子进程继承；日常 Python/uv/Ruff/mypy 缓存统一在 `.superdsh-work/web-admin-tools`，测试缓存仍归独立验证目录。动态版本元数据解析早于应用入口，必须单独防止其向源码写入字节码；禁止通过忽略规则掩盖重新生成的源码缓存。
- 编码前确定领域归属、公共契约、版本来源、规范路径、测试目录与错误语义；遇到已有实现需要拆分时同步调整调用者和测试，不建立长期转发层掩盖边界。
- `web-admin:check` 必须纳入格式、TS/Python 类型、架构依赖、版本来源、路由、测试目录和打包边界检查；不得用大范围豁免或删除检查换取通过。
- `web-admin:parity` 同时验证无版本规范入口与旧入口映射的业务等价，覆盖 Cookie、OAuth、WS、下载与幂等。兼容映射是登记的入口差异，不是新增业务版本。
- 代码审查检查职责分离、中文注释、错误和清理路径、通用扩展能力；自动检查不能替代语义审查。
- 实施交付附实际执行命令与结果，未执行或缺少环境的检查明确保留未完成；规范和计划中的任务不得在没有证据时勾选完成。
