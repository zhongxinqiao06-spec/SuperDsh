# 星桥办公与星桥娱乐 Web 实施记录

完整创作流程按[菜单、交互与业务重构方案](starbridge-studio-workflow.md)和[数据表与一致性设计](starbridge-studio-data-design.md)推进。2026-11-15 阶段 A 已落地，当前六个二级菜单、作品内八步导航、结构化存储和验收见[第一阶段交付记录](starbridge-studio-foundation-delivery.md)。本文保留双产品原始实施记录，旧的媒体验收不能替代阶段 B/C/D 的后续验收。

## 入口和授权

新 Web 管理端已接入五类角色及两级菜单。产品授权、成员管理、角色切换和真实登录验收详见[双产品角色与菜单实施记录](starbridge-product-roles-and-menus.md)。

两套工作台共用登录、角色管理、模型凭据、文件存储以及 DSH 运行时。首页有办公与娱乐入口。双产品账号登录后进入 `/#/products`，单产品账号直接进入对应首页。原办公工作台、历史会话和文件链接继续使用原路径。

迁移为已有角色补充 `products.office`，为内置管理员补充 `products.entertainment`。新建普通账号默认使用办公。管理员可在角色管理中分配娱乐权限，参与创作的角色还需要会话读写、模型使用权限，上传与收藏素材需要文件读写权限。各作品、素材版本、媒体预览和导演工具都在后端校验所有者。

## 三阶段落地

### 产品菜单与工作区

办公、娱乐共用登录、控制台侧栏、面包屑、主题、窄屏抽屉及管理页面。办公保留会话和交付入口。娱乐首页直接打开当前账号的作品列表。双产品用户从侧栏品牌旁的“切换产品”选择工作台，单产品用户登录后直接进入有权使用的产品。

| 创作工作台二级菜单 | 页面内容                                                               | 用户操作                                                                                         |
| ------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 作品项目           | 作品名称、镜头数与已采用数、工程版本、最近更新时间                     | 搜索作品，或通过“新建作品”命名后直接进入剧本；点击已有作品继续编辑。                             |
| 素材库             | 个人素材与跨作品的素材引用，显示类型、来源和具体版本                   | 按名称、作品或类型筛选，预览素材，将某一版角色、场景或媒体引用到所选作品；从作品素材返回该工程。 |
| 制作任务           | 汇总所属作品中的镜头生成、配音和导出记录，显示状态、更新时间及失败原因 | 按作品、类型和状态筛选，查看已完成的结果，或返回对应作品的任务区继续处理。                       |

打开作品后分为“剧本与导演、项目素材、分镜板、剪辑时间线、制作任务”五个页签。用户在同一作品里切换页签可以保留编辑现场。页签地址支持刷新、浏览器前进后退和复制链接。例如 `/#/entertainment/<作品ID>?section=timeline` 直接打开该工程的时间线。

管理员在“用户与权限 → 角色与权限”授予产品和业务权限，再从“菜单管理与恢复”选择办公或娱乐，编辑该产品的菜单名、图标、排序、分组、可见性与角色范围。配置独立保存，恢复默认仅作用于所选产品。菜单决定导航中显示的入口，产品权限、功能权限和资源归属继续由后端校验。双产品用户从娱乐进入共享管理页时，链接会携带当前产品，刷新后仍显示娱乐侧栏。

| 阶段         | 已实现的入口和持久化行为                                                                                                                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 双产品与素材 | 独立产品首页、授权切换、智能体/技能/工具的产品归属、娱乐默认模型、按来源分发内置工具。个人素材和项目造型分别保存，工程引用具体素材版本，上传文件与素材引用在同一事务绑定。                                         |
| 剧本与生成   | 作品绑定 DSH 创作会话。导演读取剧本、建立角色、提交可逐镜确认的草案，支持局部改镜。分镜按稳定标识重排、复制和拆分。用户确认目标、模型和用量后提交视频或单句配音；候选必须手工采用。DSH 和 Web 共用媒体任务入口。   |
| 剪辑与导出   | 支持画面裁剪和顺序、逐句配音、独立字幕文案和时间、背景音乐和音量。保存产生工程修订，恢复旧版本产生新修订。MP4 导出冻结提交时的工程和候选。可在任务页预览、下载或收入素材库。上传以分片流式合并，预览读取字节范围。 |

## 百炼与 FFmpeg

本机的真实配置在 `apps/web-admin/backend/config/model-defaults.json`。后端启动时同步该文件，供应商密钥只进入后端凭据存储。其他部署可以从[百炼媒体配置示例](../../apps/web-admin/backend/config/studio-media.example.json)选取连接与配置，合并进自己的启动配置并填写自己的凭据。示例文件不会自动覆盖管理员设置。

文生视频、参考图生视频和角色配音分别配置。同批可以混合有参考图和无参考图的镜头，确认框按实际用到的能力分别展示模型。角色可保存默认音色，单句可覆盖。模型管理支持为娱乐单独选择默认模型。已停用、无角色授权的模型不能执行已冻结任务。

生产后端镜像包含 FFmpeg。Windows 和 macOS 开发环境从锁定的 Python 依赖取得可执行文件；Linux 主机开发环境需要 `ffmpeg` 在 PATH，或使用 `WEB_ADMIN_FFMPEG_EXECUTABLE` 指定其路径。前后端仍可分别通过 `uv run python main.py` 与 `npm run dev` 启动。开发时的 PostgreSQL、Redis 等依赖按[管理端启动文档](../../apps/web-admin/README.md)启动。

使用代理合成 DNS 时，将百炼连接的准确 HTTPS 来源加入 `WEB_ADMIN_PROVIDER_ALLOWED_ORIGINS`。媒体下载识别百炼返回的 DashScope OSS 分桶，并在固定解析地址后校验原域名 TLS。下载不携带模型凭据。媒体结果放在后端持久数据目录的 `studio/media` 下。
