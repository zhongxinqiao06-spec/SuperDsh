# Web Admin 视觉与公共组件统一方案

当前目标是将新管理端整理为克制、清晰的企业级 AI 控制台：通过统一信息层级、控件尺度、页面结构和状态反馈，提高可读性与操作效率。保留黑白灰品牌基调、若依职责分层和现有业务能力。

2026-11-11 已完成全站布局调整。当前规范以聊天模型页为主列表示例，最近一次验收范围和证据见文末。

## 已定位的根因

### 弹窗滚动归属与长文本高度不合理

`assets/styles/element.css` 让整个 `.el-dialog` 滚动，`management.css` 再叠加高度和滚动规则。通用 `ManagementDialog.vue` 的动作区位于表单内容中，无法统一保证长表单的动作始终可见。

智能体编辑器又在局部样式中把文本框固定为 64px，并用 `!important` 约束最小高度；`ResourceChoices.vue` 将资源列表限制为 192px。在 1440×1000 视口，编辑弹窗可见高度 848px、内容高度 1474px，形成弹窗、四个溢出文本框、两个资源列表共七处滚动。

旧版 `apps/admin/src/components/ui/textarea.tsx` 使用 `field-sizing-content` 和最小高度，允许内容增长。新实现保留了类似初始尺寸，却丢失了增长行为，这是可读性退化的明确来源。

### 页面工具栏和行操作混用布局规则

通用 `.toolbar` 允许换行，智能体的五个行操作直接复用它。搜索工具栏需要响应式换行，表格行操作却需要稳定宽度与明确优先级；两者不能继续使用同一条规则。多个操作同时采用边框胶囊按钮，也放大了视觉噪声。

### 公共组件覆盖不完整

原生表格与 Element Plus 表格并存，直接使用 `el-dialog` 与 `ManagementDialog` 的页面并存。局部样式重复调整输入框、下拉框、按钮和弹窗，造成同一页面内圆角、边框与高度不一致。现有主题变量可以保留，但需要补齐字号、间距、控件高度和浮层规格。

### 信息展示和页面结构未收敛

模型、存储和文件页面存在重复标题。管理页分页使用 `margin-top: auto`，少量数据时也会被推到远处。长描述、原始 MIME、时间戳和技术标识没有统一展示规则，挤占常用信息与操作空间。

## 拟定视觉规范

高级感由清楚的层级、稳定的对齐、适度的信息密度和细致的反馈组成。整体采用浅中性背景、白色内容层、石墨色主操作；深色主题使用对应语义变量。减少嵌套边框与全圆角控件，保留轻量分隔和必要的浮层阴影。

以下尺寸为实施起点，由样板页在真实内容和窄屏下校准后统一进入变量：

| 项目     | 统一规则                                                                             |
| -------- | ------------------------------------------------------------------------------------ |
| 字体     | 沿用现有字体资源与中文回退；页面标题 24px，分区标题 16–18px，正文 14px，说明 12–13px |
| 间距     | 使用 4、8、12、16、24、32 的间距阶梯；桌面内容边距 24px，窄屏 16px                   |
| 控件     | 常规输入与按钮高 36px；需要更大触控区域时使用 40px；表格操作使用紧凑规格             |
| 圆角     | 表单控件 8–10px，内容卡片约 12px，弹窗 16–20px；胶囊主要用于状态和标签               |
| 颜色     | 文本、说明、边框、背景、悬停、选中、成功、警告和危险均使用语义变量                   |
| 操作权重 | 每个页面或弹窗明确一个主要动作；次要操作弱化，删除等危险操作单独分组                 |
| 图标     | 复用 AppIcon，统一尺寸、线条感与图文间距；图标按钮提供可读名称                       |
| 动效     | 轻量淡入和状态过渡，遵从减少动态效果偏好；加载不改变按钮宽度或重建整个表单           |

主列表依次展示页面名称、工具栏、数据区与内容区底部分页。筛选和页面级操作按操作顺序相邻排列。设置卡片在对应项目旁提供编辑，工作台保留独立的会话内容与输入区。

## 智能体样板页的具体调整

### 列表

- 标题区只显示页面名称。搜索、新增智能体与复制示例集中在工具栏。
- 名称突出，说明默认最多两行；试用指令和完整说明通过详情或展开查看，保留复制能力。
- 配置列使用紧凑的资源计数，状态用统一标签；资源修订号继续读取业务记录，不混用应用发布版本。
- 直接显示编辑、试用、发布检查、发布或取消发布、删除。发布状态与账号权限决定可用动作，删除需要确认，忙碌期间阻止重复提交。
- 日期按统一格式有意分成日期与时间，避免随机断行。列表独立滚动，分页留在主内容区底部。
- 窄屏切换为资源卡片，名称、状态和常用操作直接可见；复杂日志表可以使用明确的局部横向滚动。

### 编辑器

采用宽编辑弹窗，桌面目标宽度约 960px，受视口限制；窄屏使用全屏编辑。标题、关闭与底部“取消、保存”保持可见，中间内容区滚动，滚动条与关闭按钮分开占位。

使用四个清晰分区：“基本信息、行为规范、资源关联、示例与发布”。桌面可用页签，窄屏同样保留明确的当前位置。切换分区保留同一草稿；校验失败自动定位到对应分区和字段，保存仍为完整事务，不做分区隐式保存。

- 基本信息：名称、用途说明；短说明自适应增长。
- 行为规范：技能选择策略、工作要求；工作要求有足够的初始高度，随内容增长，超长内容可展开集中编辑。
- 资源关联：按知识库、技能、工具切换；支持搜索、已选数量和已选摘要，避免同时摆出多个狭小滚动框。资源定义仍在各自模块维护。
- 示例与发布：推荐指令、输入要求、输出示例使用可逐项编辑的列表；发布开关和影响说明集中展示。保留原有字段与数据格式，适配放在领域方法中。

长文本允许合理的局部滚动，但不再一律固定为 64px。外层弹窗只有正文滚动，不出现整框滚动再嵌多层滚动的结构；关闭时对未保存修改提供明确保护。

Office 场景只体现为普通资源配置与示例内容，公共组件不按“Word”“PPT”等助手名称分支。

## 公共组件与样式职责

沿用 Vue3、TypeScript、Element Plus 和若依目录，复用现有组件并补足职责。组件负责展示和交互契约，领域 composable 负责用例与状态，API 层负责请求，纯格式化与列表转换放领域 utils。

| 归属                        | 实施内容                                                               | 边界                                                               |
| --------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `components/layout`         | PageHeader、实际需要的 PageSection                                     | PageHeader 只呈现页面名称，领域操作归属工具栏或设置项              |
| `components/management`     | FilterBar、ManagementList、DataTable、RowActions、ManagementPagination | 工具栏集中页面操作，行按钮直接展示，主列表独立滚动，子列表就地分页 |
| `components/overlay`        | 改进并归档既有 ManagementDialog、ResourceHistoryDialog                 | 一套标题、正文、底栏、关闭与忙碌规则，保留 Element Plus 焦点管理   |
| `components/form`           | FormSection、LongTextField；改进并归档 ResourceChoices                 | 字段说明、错误、长文编辑与资源选择；字段值仍由领域表单管理         |
| `components/feedback`       | 扩展既有 ResourceStatus                                                | 区分首次加载、后台刷新、空结果、无权限、失败和重试                 |
| `components/base`           | 沿用 AppIcon                                                           | 图标统一入口，不复制图标实现                                       |
| `views/<domain>/components` | 智能体、技能、模型等业务编辑器                                         | 保留领域结构和业务动作，避免万能 JSON 表单或全能组件               |

迁移目录时同步更新所有调用方与测试，不保留无意义的转发文件，不为计划中的职责预建空目录。通用按钮、输入和选择器直接复用 Element Plus 的统一皮肤，只在确有跨页行为时增加组件。

样式保持单向职责：`tokens.css` 管理语义变量，`base.css` 管理基础排版，`element.css` 管理组件库外观，`layout.css` 管理全局布局，管理页和工作台样式各自管理领域布局。页面局部样式只处理独有结构，不复制全局控件皮肤、不靠新增 `!important` 叠加修补。

文件类型、日期、状态和长标识使用公共展示规则：优先展示人能识别的名称，技术值通过次要说明、详情或复制入口保留。错误必须保持失败语义并提供恢复入口；设备页的登录迁移问题需单独定位，不能用空列表掩盖。

## 验收条件

- 每个管理页面有一个主标题。短列表与长列表的分页都位于内容区底部，左侧显示总数与范围，右侧显示每页条数与翻页控件。滚动列表后最后一行完整可见。
- 390、768、1280、1440px 视口下没有页面级横向溢出；必要的宽表在独立区域滚动，常用管理操作在窄屏可直接访问。
- 长表单的标题、关闭和保存始终可达；正文滚动不带走操作区。长中文、英文标识、大量资源和超长说明不挤坏布局。
- 桌面操作列按实际按钮数分配宽度。全部记录动作直接呈现，窄屏可换行，保留权限、禁用原因、危险确认和忙碌反馈。
- 空数据、筛选无结果、首次加载、刷新、失败、无权限、保存中和校验错误分别表达；异步更新不清空草稿或造成布局闪动。
- 明暗主题均检查正文与说明、边框、焦点、禁用和状态颜色；键盘可完成弹窗、页签、菜单和表单操作，关闭后焦点返回触发点。缩放与辅助技术的独立验收范围在执行记录中单列，不从响应式截图推导通过。
- 智能体保存、发布检查、发布切换、试用、删除与资源绑定保持语义一致；模型默认值、权限、历史会话、终止任务和成果入口通过对应回归。视觉测试使用隔离的合成数据，不以真实外部模型调用作为样式验收前提。
- 新测试放 `apps/web-admin/tests`，截图、日志、缓存和临时数据放 `.superdsh-work/web-admin-validation/<run-id>`。只清理本次专属测试数据，不修改用户现有记录。
- 执行前端类型、格式、架构检查及适用的组件和浏览器回归；保留改造前后同视口截图。旧包基线继续检查，未验证项独立记录，不从页面可打开推导全量功能通过。

本方案不改变后端配置目录、启动命令、部署入口、版本来源或执行引擎。公共契约、复杂交互和生命周期处理按现有规范补充有意义的中文注释。

## 2026-11-10 首轮实施与验证记录
