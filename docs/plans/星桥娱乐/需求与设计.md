# 星桥娱乐：需求与设计

更新基准：2026-11-18。本文统一描述产品需求、现有交互与接口、验收证据及剩余工作；数据库字段见[数据字典](数据字典.md)，公共边界见[整体架构](../整体架构.md)、[开发规范](../开发规范.md)和[页面设计](../页面设计.md)。

当前已完成创作基础、作品准备、个人库制作、批量制作与 AI 局部编辑。已从用户参考图完成《噜噜游记》四镜、20 秒竖屏短片，并在原服务器打开工程、播放及下载。自动排时、拖动剪辑、完整交付检查与可选编码规格仍未完整交付；已有成片不能替代这些能力的验收。

## 1. 产品任务与边界

用户可以从一句想法、已有剧本、上传形象或个人库角色开始，得到可继续编辑的多角色配音短片。制作单位是稳定身份的镜头，最终采用结果由时间线决定。作品现在分为快速视频、分镜作品与系列短剧：前两类各有一份当前工程，系列组织多份独立的单集工程；暂不引入季、拍摄组或多人协作组织。

- 关键决定由用户作出：采用剧本建议、确定人物和声音、确认分镜与试片、确认本次生成范围、采用媒体、最终导出。打开抽屉、预览候选、进行预检不应触发收费生成。
- DSH 负责导演会话、模型推理、工具决策和会话队列。持久媒体任务负责视频、配音、图片及导出，不另建 Agent 执行循环。Web 和 DSH 工具进入同一领域服务。
- 角色、环境、道具、模型与供应商均通过能力及版本引用装配。办公工具不构成创作域的固定流程分支；两端使用同一平台。旧 `apps/admin` 不修改、不作为回退依赖。
- 手工编辑始终可用。无角色、无台词的作品无需补假角色或假音色；有缺项仍可继续构思，实际制作和导出才校验相关硬依赖。
- 已生成结果不因改稿、换默认模型或重新排序被删除。新候选必须明确采用；保存与确认回执不能只存在前端内存。

### 创作中心与我的作品

登录后，侧栏首项「首页」打开 `/entertainment` 创作中心。它位于「创作工作台」上方，收起分组仍然可见。在创作中心选择快速创作直接打开快速编辑器，选择分镜创作或系列短剧进入各自的创建页。分镜提交后进入剧本编辑，系列提交后进入「故事与分集」。旧的 `?create=series` 入口同样进入系列创建页。

「我的作品」位于 `/entertainment/works`，用于检索、查看、继续制作和归档作品。同一账号从编辑器返回时恢复已应用的分类、范围、搜索条件和页码。只读账号可以打开已有作品。

三种模式共用素材中心、模型配置、权限、媒体任务和 DSH。它们属于“我的作品”的分类，不是新的产品或三套运行时。`GET /api/studio/works` 在服务端统一搜索、分类、归档过滤、排序和分页；系列内单集及移出的历史单集不重复出现在顶层作品目录。旧作品默认归为分镜作品，原链接保持可用。

| 模式     | 入口与主要任务                                                                          | 保存与生成边界                                                                                                                               |
| -------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 快速视频 | `/entertainment/quick/{id}`；一句话、单图或多个参考生成一条视频，左侧输入，右侧比较候选 | 新建、改提示词和预检不生成。明确确认冻结计划后只提交一个任务；重复点击返回原任务。结果可下载、收藏到个人库，或以同一作品 ID 转入分镜工作台。 |
| 分镜作品 | `/entertainment/{id}`；沿用八阶段制作                                                   | 原有剧本、角色、分镜、配音、剪辑、交付流程保持；快速模式升级采用所选候选的输入快照，不用后来改写的提示词冒充生成来源。                       |
| 系列短剧 | `/entertainment/series/{id}`；整剧总览、故事与分集、本剧设定、剧集制作、成片交付        | 整剧负责故事与版本组织，每集继续引用一个既有制作工程。新建可按计划集数建立空白草稿，不自动生成故事或视频。                                   |

快速版的模型、可用输入方式、时长、画幅和参考数量来自后台能力。没有可用配置时显示具体缺项，不放假选项；当前视频适配器不支持的编码、音频参考或供应商专属功能不提前展示。提示词 AI 优化复用正文选段修改与对比采用/撤回，保存的快速草稿与正文镜像同事务更新。候选按提交时固定编号，轮询和未知受理核对不改变编号；选中只是预览，不自动转分镜或收藏。

快速任务沿用制作取消与核对：刷新恢复原任务，不重发。已有相同输入的成功候选先提示预览，明确“再生成一个候选”才新建；供应商受理未知须先核对，另行生成需要明确承认可能重复计费并保留原记录。

### 系列短剧的用户操作

1. **确定整剧方向。** 从娱乐首页“创作中心”选择“系列短剧”，进入独立创建页，填写作品构想、连续剧情或单元故事、计划集数与每集目标规格。标题与底部操作固定，正文独立滚动；关闭未保存内容须确认，失败保留输入。创建后进入分集编排；计划集数调整不会删除已有集。旧新建链接转入同一创建页，未提交时不创建作品或调用模型。
2. **编排故事。** 左侧是按播放顺序排列的分集，中央编辑本集要讲什么、开场、冲突与转折、结尾和前后集衔接。保存只保存故事草稿；“确认故事，进入制作”才同步到本集正文。切集、切区和离开先保存或放弃未保存内容；关闭确认框保持当前草稿。
3. **请 AI 协助。** 右侧助手先显示本次选择的集与要求，用户明确发送。后台冻结原文与范围，DSH 通过 `studio_series_suggest` 只写待审建议。用户逐集、逐段比较采用，未选集和字段不变；手工改动发生冲突时拒绝覆盖。待审建议、生成中的请求可刷新恢复，放弃后迟到结果不复活。
4. **调整集序与结构。** 移动或拖动改变集序，工程和媒体跟随稳定集 ID。已有独立分镜作品可以加入整剧，原工程不复制。拆分/合并先编辑新故事、查看冻结方案再确认；当前实现只拆合故事，原镜头、配音与剪辑不自动搬迁，源工程以只读历史保留。合并仅支持连续集；移除本集也不物理删除历史工程和资源。
5. **确定本剧设定。** 从个人库选择角色、场景与道具的具体版本，保存新的整剧设定版本后，再勾选要同步的集。未选集维持原版本，已有单集手工覆盖不被静默替换；已采用媒体与剪辑不随设定更新而重做。
6. **进入单集制作。** 从整剧继续进入原八阶段工作台，顶部保留所属剧、切集和本剧设定入口。已确认故事、角色和素材继续使用真实工程修订。锁定或整剧归档后，原链接仍可读，后端阻止故事、工程、媒体提交与采用等写操作；解锁是明确动作。
7. **汇总成片。** 整剧制作页汇总真实镜头/采用数；成片交付页仅展示已成功导出的单集，可播放、下载与返回版本。工程后来有修改时标出交付修订与当前修订差异。整剧一键收费生成、整季 ZIP 和自动跨集剪辑属于后续能力，当前没有隐藏批量提交。

整剧修改、重排、设定同步、建议采用与拆合使用整剧修订及幂等请求号；同步正文另校验单集工程修订。已锁定或交付的集不参与隐式重排/结构改写；预览后再锁定也会在最终确认时重新检查。任何系列、单集、建议或资源访问均检查当前账号、娱乐产品权限与本人归属。

## 2. 菜单与权限

娱乐侧栏保留两级。作品内八步是当前作品的上下文导航，不是第三层 RBAC 菜单。素材中心分为角色、场景、道具和媒体四个入口，共用查询、版本、上传、制作与引用组件。

| 一级       | 二级     | 模块与路由                                            | 主要交互                                                                |
| ---------- | -------- | ----------------------------------------------------- | ----------------------------------------------------------------------- |
| 顶层首项 | 首页 | `studio.create` · `/entertainment` | 选择快速创作、分镜创作或系列短剧，进入对应创建页或编辑器 |
| 创作工作台 | 我的作品 | `studio.projects` · `/entertainment/works` | 搜索、继续制作、归档/恢复；展示真实封面、镜头及采用数量、更新时间 |
| 创作工作台 | 制作任务 | `studio.tasks` · `/entertainment/tasks`               | 汇总本人作品及个人库任务，定位镜头/台词/设定，处理失败和待核对          |
| 创作工作台 | 成片交付 | `studio.deliveries` · `/entertainment/deliveries`     | 复用任务目录查询成功导出；预览、下载、返回对应作品                      |
| 素材中心   | 角色库   | `studio.characters` · `/entertainment/characters`     | 名称、外观、造型版本、声音试听与采用，引用到作品                        |
| 素材中心   | 场景库   | `studio.environments` · `/entertainment/environments` | 地点及日夜、天气变体，关联剧情场次；单个镜头可覆盖场景                  |
| 素材中心   | 道具库   | `studio.props` · `/entertainment/props`               | 道具设定与参考图，选择具体版本用于镜头，追溯使用位置                    |
| 素材中心   | 媒体库   | `studio.library` · `/entertainment/library`           | 图片、视频、配音、音效及音乐；采用后真正进入剪辑与导出                  |

前述入口同时要求 `products.entertainment`。作品读写分别要求 `studio.projects.read/write`，个人素材要求 `studio.assets.read/write`；调用模型、导演会话及文件操作继续要求相应 `models.use`、`sessions.*`、`files.*`。后台同时检查本人资源归属。当前取消/核对沿用任务所属作品或素材的写权限；独立的 `studio.generate/export/jobs.cancel/jobs.reconcile` 是进一步细分目标，不能当成已部署权限。

五角色及公共菜单以[整体架构](../整体架构.md)为准：超管可见两端完整管理菜单，办公/娱乐管理员只管理各自产品，办公用户和娱乐创作者使用本人资源。管理员资格不等于读取他人私有剧本和成片的授权。“办公管理员＋娱乐创作者”在娱乐侧不能管理成员、菜单、默认模型或供应商。

产品切换重新读取当前产品菜单、模型和资源，取消旧请求；有未保存修改时提示保存或放弃。共享管理页面保留来源产品上下文。菜单隐藏不等于撤权，直接请求接口仍检查服务端授权。创作预设菜单与其版本绑定属于后续设计，当前菜单注册目录未发布该入口。

作品地址为 `/#/entertainment/{project}?section=<阶段>&shot=<稳定ID>`。阶段键为 `brief/script/cast/storyboard/sample/production/edit/delivery`；旧 `library/timeline/jobs` 分别映射到 `cast/edit/production`，保留作品和镜头定位。菜单升级保留自定义名称、隐藏、排序及角色限制，不覆盖办公菜单。

顶部展示作品名、规格、保存状态和当前主要动作；大段要求可展开，任务标题优先镜号与场景。内容在前，阶段审阅在后。桌面按可用宽度组织内容/画面/属性，窄屏切换展示，不能把八个步骤和多列属性硬挤在一行。抽屉复用公共组件：标题与底部操作固定、正文单滚动，避免表单内部再套多个长滚动区。

当前服务端持久确认只覆盖 `script/cast/storyboard/sample` 四个准备阶段，实际派生状态为 `blocked/needs_review/confirmed/skipped/stale`。八步导航可随时进入，不等于八步都已有独立确认表。完整目标状态 `not_started/in_progress/...` 暂不映射成不存在的数据库枚举。

## 4. 剧本编排与公用 AI 协作

### 从没有剧本开始

1. 用户输入构想，可上传参考形象或选择个人库具体版本。不要求先编好全部剧本。
2. 起草抽屉显示本次目标、已有参考与可用能力；用户选择是否读图、是否联网及补充要求。单纯打开不启动模型。
3. 所有选定能力、文件权限、图片真实格式/像素/总数量先统一预检，再调用公共参考资料服务。多图逐张解析，不把一段混合描述写进每个角色。
4. 同作品范围、账号、配置修订和输入完全相同的成功读图结果可复用；联网不以无时效缓存冒充新查询。网页来源只呈现供应商实际返回的有效引用。
5. 准备结果交给既有 DSH 导演。原始正文保留，建议进入方案比较，用户采用后才写工程。参考资料本身不自动生成视频或配音。

当前输入契约：`assetIds`、`uploads` 各最多 4 项；上传图为 PNG/JPEG/WebP、单张不超过 20 MB、像素不超过 4000 万；合并去重后的实际图数还必须满足所选模型 `maxImages`。不通过配置名硬编码具体模型。未配置能力时允许关闭该项先构思，不伪造联网结果。

导演工具绑定过期时提供用户明确触发的更新；运行中禁止重绑，旧冻结绑定与历史保留。工具准备/确认卡展示有权读取的实际动作与参数，读取失败阻止盲目确认。内置草稿工具只保存建议，第三方声明草稿不自动豁免执行审批。

### 原稿、场次与局部修改

桌面展示原稿与场次目录，选择一场才展开其内容；手机顺序展示。选取原文可建场或关联当前场次，场次稳定 ID 不随排序变化。有镜头引用的场次先重新分配镜头再移除；空场次删除需确认。

“AI 修改选段”和“AI 修改本场”共用 `AiTextComparison`、`useTextEdit` 与原 DSH 会话用例。先保存，再冻结修订、Unicode 字符范围、原文和操作号。原有未关联正文的场次明确引导关联，不能以摘要冒充本场全文。

编辑记录状态为 `waiting → ready → applied → undone`；等待或未采用建议可以 `discarded`。用户可在对比中继续手改建议，采用时仅更新冻结范围并调整场次关联位置；回看显示实际采用文本。撤回是局部逆向修改，保留范围外后来保存的文本和其他工程修改。重叠修改、场次重关联或重复片段无法可靠定位时拒绝覆盖。关闭面板保留当前页草稿，最近 30 条持久记录可刷新恢复。放弃等待中的建议请求 DSH 中断，迟到建议不能复活。

本次范围使用 Unicode 码点偏移，不是 UTF-16 下标或时间码。单次编辑 1～12000 字；完整段落身份、场次拆分/合并、整篇一致性检查仍为后续目标。

### 建议与手工修改共存

导演方案比较基线、当前与建议三份内容，覆盖场次、镜序、角色/参考、台词、动作、时长及增删。选择无冲突项只勾选，不自动采用；冲突需明确覆盖。原文模式的导演提议不得改写原稿或新增原文外台词，手工编辑仍由用户决定。确认本阶段与采用部分提案是不同动作，保存失败、待审方案或审阅期间内容变化不能直接跳到下一步。

## 5. 个人库、作品库与版本

“角色/场景/道具身份”和“媒体文件身份”分开：一个角色可以有多个造型和声音版本，一个版本可以关联多张参考图。故事场次表达叙事顺序，场景素材表达可复用环境，两者不是同一对象。

- 个人库提供跨作品复用；引用到作品建立本片身份/版本来源，作品绑定具体版本。同一个角色可在本片使用多个造型。
- 个人库独立生成参考图或试听，不创建隐藏作品。先预检确认，结果进入候选，采用时追加版本；已有作品引用不跟着改变。
- 多个作品/镜头可以引用同一文件。替换一镜的引用只改变该镜；收藏与派生保留来源链，不复制无意义的二进制。
- 当前版本指针是目录默认，不代表所有镜头当前采用。角色换装默认保留声音；改声音只影响选定范围的配音。
- 当前文件、生成候选、不可变修订与交付仍可能引用旧媒体；归档不物理清理文件。

准备候选采用生成新设定版本并更新本片对应引用，台词角色引用随版本调整；已采用视频、配音和裁剪保留。跨作品角色引用可复用声音绑定，但不继承另一作品私有试听链接。

### 素材中心与作品的双向工作流（2026-11-18）

目录按稳定身份聚合，一张卡代表一个角色、场景、道具或媒体族。个人库与作品素材通过可见页签切换；历史修订收在详情中，造型/环境变体具有独立的当前版本。所有选择器共用搜索、分页、预览与明确确认；打开或预览不写工程。

1. 在作品设定卡点击“收藏到库”，默认保存当前采用的参考图、说明和声音。可收藏为新条目；已有来源时可保存为原造型的新版本，或命名一个新造型。重复提交复用回执，不能凭相同名称覆盖其他条目。
2. 从库选用具体版本，建立本片引用与来源关系；修改本片不会改动其他作品。库内新版本只提示，不自动替换。
3. 采用更新前比较原引用版本、本片和库内版本，分别选择名称、说明、参考画面及声音；冲突需要明确覆盖。本片已生成视频、配音、台词及手工裁剪保留。
4. 剧情场次绑定默认场景，镜头可单独覆盖。镜头按角色、场景、道具、其他视觉参考分组选择，实际生成输入消费这些引用。导演参考资料共用素材选择器，保留用户选择的角色、场景、道具版本。
5. 视频、配音、音乐及音效可直接从库用于剪辑；库内视频与生成候选互斥，库配音与生成配音互斥。采用视频前读取实际时长；不够时需用户确认调整。音效支持全片时间或镜头锚定，随镜头排序与裁剪移动。
6. 归档只影响库目录，已有作品、历史版本与导出引用保留。读取来源与编辑目标分别校验权限和归属；菜单资格不提供跨账号私有素材访问。

新增契约：`GET /api/studio/library/{asset}/detail`、`POST /api/studio/library/collections`、`POST /api/studio/projects/{project}/library-imports`、`POST /api/studio/projects/{project}/library-updates/preview` 与 `/apply`、`POST /api/studio/library/{asset}/archive`。媒体时长通过 `GET /api/studio/assets/{asset}/metadata?project=...` 探测；保存来源字段为 `sceneAssetId`、`videoAssetId`、`audioAssetId` 与 `soundEffects`。旧任务引用继续兼容，不另建执行队列。

本轮代码与定向验收已完成，尚未提交或部署。版本比较逐字段记录基线：库内未改的字段不回滚本片手工修改，未勾选的库内变化在下次比较中仍保留。实际通过范围见第 10 节，不能据此推导全站和真实供应商全部重新验收。

## 6. 预检、生成、取消和核对

### 明确一次制作意图

制作计划使用 `missing/failed/selected/all` 四种实际选择模式；`missing` 同时包含缺失和输入已变化的 `outdated`。仅重做失败项不等于重发有回执的下载故障，后者优先恢复原任务。独立 `stale/variant` 是旧目标命名，不是当前 DTO 可传的枚举。

每项显示镜头/台词、模型显示名、秒数/字数、音色、参考数量、选择/复用/跳过原因与阻塞。确认携带 `planHash`、`revision`、`requestKey`；重新核对工程、权限、模型与任务状态。输入变化返回冲突并要求重新预检，不悄悄扩范围或换模型。同号不同请求拒绝，同号相同请求复用原回执。

实际候选状态派生为 `missing/outdated/active/ready/failed/recoverable/uncertain`。费用字段当前可空，界面如实提示未知。原始计划中的“缺失、活动、过时”等不是媒体任务状态，不混在一个下拉中解释。

### 任务状态与允许动作

| 实际状态      | 用户含义                   | 恢复/取消行为                                    |
| ------------- | -------------------------- | ------------------------------------------------ |
| `queued`      | 尚未提交                   | 可原子取消，防止执行器继续认领                   |
| `submitting`  | 已记录提交意图             | 进程中断或结果不明转 `unknown`，不重排成新提交   |
| `polling`     | 已有原回执                 | 查询同一个供应商任务                             |
| `downloading` | 正在收集结果               | 按原回执恢复下载与媒体校验                       |
| `ready`       | 可审看结果                 | 进入候选，明确采用后才改变工程                   |
| `failed`      | 有明确失败或收集故障       | 区分安全重做与原回执可恢复，不能一律再生成       |
| `unknown`     | 受理结果未知               | 冻结自动重发，核对供应商记录                     |
| `paused`      | 本地已停止处理             | 远端可能仍执行/计费，可核对并恢复收集            |
| `cancelled`   | 未提交已取消或远端确认取消 | 不把仅停止本地等待显示为远端取消成功             |
| `unaccepted`  | 已记录人工未受理结论       | 保留依据；另行生成仍要求明确范围、原因与风险确认 |

取消/核对接口动作是 `cancel/resume/receipt/unaccepted/keep`。仅可信原回执可恢复，浏览器提供任意供应商任务号不能认领。已受理视频只有供应商确认取消才改为 `cancelled`；迟到结果不覆盖取消意图。用户明确另行生成时记录替代计划和原因，原未知任务保留。停止导演对话与取消媒体任务不是同一个操作。

图片、视频、配音复用公共供应商传输与凭据授权，媒体任务目前仍有专用加密提交/结果收据；不能把旧目标 `studio_job_attempts → model_operations` 全链归一宣称已实现。参考资料 AI 已使用公共 `ModelOperationService`，读取超时与连接失败分别报告，Responses SSE 响应 ID 到达即保存；未知操作不自动重放。

## 7. 剪辑、预览与交付

当前工程包含画面、角色配音、字幕、音乐四类轨道表达。已实现按稳定镜头排序、画面入出点、逐句音频起点和音量、独立字幕文案/时间、音乐和工程修订恢复。界面只展开当前镜头，切镜保留未保存编辑；历史版本按需展开。恢复旧版创建新修订，不倒退计数或修改既有交付。

当前正式渲染读取冻结文档及画幅，使用已采用视频、独立配音和音乐；不会把供应商视频原声音轨冒充角色旁白。MP4 采用 25 fps、48 kHz 音频，720P 档画布支持 16:9、9:16、1:1、4:3、3:4，通过等比缩放和补边适配。用户目标时长与实测成片时长分别表达。导出中继续编辑不改变当前导出内容。

已有静态分镜预演可以结合采用的配音查看节奏，但不改工程；正式成片预览使用渲染结果。当前还没有完整的自由多轨浏览器组合预览、自动排时、拖动裁剪、锁定字段、声音越界处理向导和统一交付检查清单。多句默认起点重叠、手工裁剪截音等必须在后续阶段解决，不能靠一个成功样片证明已覆盖所有对白时序。

局部修改应遵循：

| 修改            | 需要更新/核对              | 应保留                          |
| --------------- | -------------------------- | ------------------------------- |
| 校正字幕        | 字幕、预览及后续导出       | 原配音与画面                    |
| 改一句台词      | 本句配音、字幕与排时       | 其他台词、未依赖该音频的画面    |
| 第三镜换雨夜    | 本镜环境参考、画面及导出   | 人物造型、原台词/配音、其他镜头 |
| 换角色造型/声音 | 用户选定作用范围的相关结果 | 其他作品固定版本与未选镜头      |
| 重排/裁剪       | 时间线、字幕/音画边界检查  | 原媒体与其他手工调整            |
| 改整体画幅/风格 | 展示受影响项并明确选择策略 | 全部旧候选供比较                |

输入指纹按实际视觉或声音依赖计算，不以作品修订号让所有结果失效。完整“有意采用过时结果的理由与输出例外”结构化留存仍属于目标设计，详见数据字典。

## 9. 一致性、错误与升级

自动保存防抖，有保存中/成功/失败反馈；提交期间的新输入不丢失。响应丢失后保留原请求号，版本冲突停止自动写入，载入远端前明确提醒。切产品、离开作品及关闭窗口保护草稿。只读初始化和轮询错误可以受限恢复，写入不能无条件自动重发；历史 502 未持续复现时不杜撰根因。

慢网络和媒体探测不持有业务写事务。短事务检查归属、修订、指纹后更新相关实体与回执，队列随后提交外部任务。供应商结果先收集校验，完整文件才进入 ready；实际取消、恢复与迟到写回使用行锁/条件状态。

当前迁移链最终为 `fd940fa517cd`。基础迁移保留旧 ID、历史修订和回执，将旧素材转为身份/版本及只读兼容视图；不可访问素材、来源环或不完整工程导致事务回滚，不静默跳过或 stamp。保留正式数据与运行卷，不能沿用早期“只有测试数据可清库”的假设。开发入口仍是后端 `uv run python main.py`、前端 `npm run dev`，worker 每代监听前完成迁移，避免页面先请求缺表接口。

跨服务器同步使用[受限导出工具](../../../apps/web-admin/tests/tooling/export_studio_project.py)及[受限导入工具](../../../apps/web-admin/tests/tooling/import_studio_project.py)：指定目标 owner，默认 dry-run，拒绝覆盖同 ID，校验外键闭包与文件哈希，单事务提交。会话队列与来源实例密文不移作可执行状态，导演会话在目标重新创建，未知操作只留证据。不得全库覆盖已有账号或办公数据；提交结果未知时先核对，不自动再次导入。

#### 软件、K 线与媒体制作约束

1. 交易台采用本片统一的模拟软件界面，含行情、K 线、成交量、时间周期、持仓和操作记录。界面用清晰中文与可检验的模拟数据制作；每个镜头只突出正在讲解的一个操作，手机画面不塞满小字。噜噜的鼠标动作、指向位置与界面状态变化对应。
2. K 线与关键数字来自同一份冻结数据，满足最高价不低于开收价、最低价不高于开收价、时间单调等校验。价格、持仓、台词、字幕与操作回执一致；比较图使用同一基期或明确的归一化，不能直接拿三个不同指数的点数比高低。涨跌同时使用正负号、箭头和文字，不只依赖各市场不同的颜色惯例。
3. AI 负责角色、场景和动作候选；精确文字、数字和图表采用确定性制作的画面或视频素材，经项目素材库进入同一工程。模型生成的乱码图表不能作为教学依据。若现有产品缺少所需叠层/对齐/画面合成入口，登记为功能缺口并补齐后复验；不得把外部拼好的最终片导入后宣称完整流程已通过。
4. 先试“噜老师操作软件 → K 线变动 → 暂停讲解”的一个难镜，再生产整集。每句配音按实际时长排入时间线，音乐低于人声；不用加速念稿或裁掉句尾强行满足目标时长。首轮普通讲解配音与表情动作配合，不将未实现的口型同步当作验收承诺。
5. 生成前从后台实际配置确认参考图、视频与配音能力，确认输入限制和预估用量；候选明确采用后才进入时间线。失败按单镜或单句修复，受理未知先核对，禁止自动重复收费。来源、角色版本、单集工程、候选与最终导出修订均可追溯。
