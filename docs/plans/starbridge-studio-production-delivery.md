# 星桥娱乐制作闭环交付记录

本阶段补齐个人库独立生成与制作闭环。只修改新管理端、配套测试和文档，DSH 继续负责导演对话与工具决策，媒体生成沿用同一持久任务队列。旧 `apps/admin` 不参与实现。

## 用户实际操作

1. **个人库制作**：在角色库、场景与道具库选择“制作素材”。无需建立作品，选择生成参考图或角色试听，查看方案后确认。生成结果先进入候选；“采用并保存新版本”才改变个人库当前版本，已有作品引用保持原版本。配音模型和音色来自后台配置。
2. **批量预检**：作品“批量制作”默认选择“只补缺失”，可切换失败项、自选镜头/台词、全部重做。预检逐项展示目标、模型、时长、字数、音色、参考图与跳过原因。损坏或无权读取的参考文件、无效音色、不可用模型、规格不匹配在提交前阻止执行。
3. **确认提交**：预检不调用生成供应商。服务端保存冻结计划与输入摘要；确认时核对工程、模型与任务状态。重复确认返回原任务。试做一镜、单镜生成和原 DSH 工具也复用同一预检服务。
4. **处理部分结果**：已有可用候选不因“补缺失”重复生成；更改实际生成输入会提示待更新。失败重做针对生成失败，有回执的下载故障优先恢复原任务。旧候选和已采用时间线继续保留，新结果不自动采用。
5. **取消与核对**：未提交任务原子取消。已经提交时停止本地处理，尝试取消供应商排队任务；仅远端明确确认取消才显示已取消。运行中的远端任务可能继续计费，页面显示待核对并保留回执。迟到响应不能覆盖取消意图。
6. **受理未知**：核对原任务仅查询、下载，不重发生成请求。优先使用服务器加密保存的原回执，拒绝认领任意外部任务号。没有可验证回执时记录人工核对依据；仍要另行生成必须明确选择范围、说明原因并确认重复计费风险。旧记录保留，新计划关联替代关系，避免永久阻塞后续补缺失。

供应商取消行为按[百炼异步任务管理 API](https://www.alibabacloud.com/help/en/model-studio/manage-asynchronous-tasks)处理。

任务目录同时展示本人作品与个人库任务；个人数据仍单独检查素材权限。任务可回到对应镜头或个人素材，取消、恢复和核对共用一个组件。全部使用现有公共弹窗、表单、按钮和间距样式。

## 数据与分层

| 对象                      | 关键字段与关系                                                                                                                                                              | 约束                                                                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `studio_generation_plans` | `owner → users`；`project → studio_projects` 或 `entity → studio_entities`；`revision`、`request_key`、`request_hash`、`plan_hash`、`intent`、`manifest`、`state`、`result` | 项目/个人设定恰有一个；账号与请求号唯一；确认绑定原计划哈希及修订          |
| `studio_media_jobs` 扩展  | `owner → users`、可空 `project`、`library_entity → studio_entities`、`cancel_requested`；输入保留 `planId`、`inputHash`、`sourceVersion`                                    | 个人任务必须具有账号和设定；个人账号/请求号/目标唯一；作品沿用既有唯一约束 |
| `studio_job_actions`      | `owner → users`、`job → studio_media_jobs`；`request_key`、`request_hash`、`kind`、`detail`、`result`、`created_at`                                                         | 账号与处置请求号唯一；取消、核对和个人采用记录可追溯                       |
| 已有素材版本              | 图片采用新建设定版本和媒体引用；声音采用保存音色及配置修订                                                                                                                  | 作品引用具体版本，个人库改变不隐式改写作品                                 |

后端按 `production_controller → ProductionService / PersonalGenerationService / JobLifecycleService → ProductionDao` 分层。`GenerationInputs` 处理只读预检，`GenerationPlans` 负责冻结与确认，纯依赖比较在 `entity/bo/production.py`。事务不等待外部供应商；发送前条件领取任务，处置和迟到写回使用行锁。

前端请求在 `api/studio/production-api.ts`，契约在 `types/studio/production.ts`，请求状态与轮询在 `composables/studio`，页面组件在 `views/studio/components`。离开个人制作弹窗取消轮询；写操作不自动重发，失败保留方案和表单。

主要接口均无业务版本前缀：

- `POST /api/studio/projects/{project}/generation-plans`，`POST .../{plan}/confirm`。
- `GET /api/studio/entities/{entity}/production`，`POST .../generation-plans`，`POST .../generation-plans/{plan}/confirm`，`POST .../adopt`。
- `GET/POST /api/studio/jobs/{job}/actions`。
- `POST /api/studio/personal-media/{job}/access` 与受短期文件范围 Cookie 保护的读取接口。

## 阶段检查报错修复

实际开发库停留在基础结构，缺少 `studio_stage_reviews` 和 `studio_proposals`；前端新步骤调用新接口时因此返回内部错误。开发入口以前只在父进程启动时迁移，热重载代码不会同步升级数据库。

本次补齐加法迁移，开发热重载每代 worker 在监听前执行迁移，迁移目录也纳入监听。应用启动按迁移元数据核对结构，不再把缺表错误留到页面请求。已只读检查当前开发库全部五张相关表及现有作品阶段检查。当前手动运行的开发服务保持运行。

启动命令保持后端 `uv run python main.py`，前端 `npm run dev`。无新增 dev 入口，缓存仍在 `.superdsh-work`。
