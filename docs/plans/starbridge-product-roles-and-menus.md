# 星桥双产品角色与一、二级菜单规划

完整重构目标见[作品制作菜单与交互方案](starbridge-studio-workflow.md)及[数据设计](starbridge-studio-data-design.md)。2026-11-15 阶段 A 已将娱乐侧栏分为创作工作台与素材中心，提供六个二级菜单和作品内八步导航，并补充作品/素材读写动作权限。当前菜单及隔离验收见[第一阶段交付记录](starbridge-studio-foundation-delivery.md)；下文保留此前角色与菜单实施记录，五角色职责不变。

已落地 Web 端的产品鉴权、五个预置角色和两级菜单。星桥办公与星桥娱乐共用 Vue 控制台、FastAPI 管理服务和账号，同一账号可以在两个产品承担不同职责。

## 五个预置角色

| 角色           | 登录落点                 | 默认职责                                                             | 授权范围                                                       |
| -------------- | ------------------------ | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| 平台超级管理员 | 产品选择                 | 可切换两个产品，看到各自全部业务、产品管理和平台管理菜单             | 管理全局账号、角色与权限、两个产品的管理员、公共连接及系统设置 |
| 办公管理员     | 办公首页                 | 拥有办公使用端功能，管理办公成员、菜单和发布给办公用户的能力         | 仅办公。可授予或收回普通办公成员资格                           |
| 娱乐管理员     | 作品项目                 | 拥有娱乐创作功能，管理娱乐成员、菜单和发布给创作者的能力             | 仅娱乐。可授予或收回普通娱乐成员资格                           |
| 办公用户       | 办公首页，可直接发起对话 | 使用已发布的办公智能体、已授权模型和工具，管理自己的会话、设备与文件 | 本人数据以及显式共享给本人的资源                               |
| 娱乐创作者     | 作品项目                 | 管理自己的作品和素材，制作分镜、配音、剪辑并导出                     | 本人作品、个人素材、任务及其媒体结果                           |

超管是一种受保护的角色，保留现有最后一名有效管理员保护。其菜单覆盖范围与他人的业务数据访问权分别处理。创作和办公权限以当前产品为边界。账号同时持有“办公管理员、娱乐创作者”时，办公有产品管理菜单，娱乐只有创作和个人菜单。两个产品权限都在时显示切换入口。

## 默认菜单树

侧栏只展开两级。表内每一行是一个一级菜单，右侧列出全部二级菜单。产品名和左上角品牌链接用于返回产品首页。窄屏复用相同菜单树和顺序。

| 适用产品 | 一级菜单   | 二级菜单（默认顺序）                                                         | 默认可见角色                               |
| -------- | ---------- | ---------------------------------------------------------------------------- | ------------------------------------------ |
| 办公     | 办公工作台 | 智能对话、历史会话、我的文件、我的设备                                       | 办公用户、办公管理员、超管                 |
| 娱乐     | 创作工作台 | 作品项目、素材库、制作任务                                                   | 娱乐创作者、娱乐管理员、超管               |
| 当前产品 | 能力管理   | 智能体、知识库、技能、工具、默认模型                                         | 本产品管理员、超管                         |
| 当前产品 | 产品管理   | 产品成员、菜单配置                                                           | 本产品管理员、超管                         |
| 两端共用 | 平台管理   | 平台总览、账号与角色、供应商与模型、扩展管理、设备运维、存储与服务、平台审计 | 超管                                       |
| 两端共用 | 个人中心   | 账号资料、账号安全、外观设置、个人模型                                       | 所有角色。“个人模型”按既有个人模型权限显示 |

“两端共用”沿用相同路由和配置数据，从哪个产品进去，返回时保留哪个产品的侧栏。普通用户默认只见业务工作台和个人中心；产品管理员增加能力管理、产品管理；超管再增加平台管理。超管可在当前产品看到完整菜单，在菜单配置中预览普通角色实际能看到的内容。全局登录、产品选择、授权回调、文件预览和只读分享继续作为独立或上下文入口。

### 用户如何操作

- **办公用户**从“智能对话”直接使用默认模型和权限，在输入栏选择已发布智能体。会话内保留项目、历史、归档等快捷操作。“历史会话”打开同一个工作台的历史视图，“我的设备”只展示已绑定给本人的设备。“我的文件”复用现有文件页。Word、Excel、PPT 作为可配置能力出现在业务流程中。
- **娱乐创作者**从“作品项目”新建或继续作品。作品内固定五个页签“剧本与导演、项目素材、分镜板、剪辑时间线、制作任务”。“素材库”支持跨作品检索和复用。“制作任务”支持查找镜头、配音及导出记录，点击某条返回所属作品。角色、场景、道具作为素材类型筛选。
- **产品管理员**进入“产品成员”管理该产品的成员资格。移除双产品用户的办公资格后，该账号仍能使用获准的娱乐功能。只有超管能任免产品管理员、创建跨产品角色、禁用或删除全局账号。产品管理员可发布本产品的智能体、技能、工具，关联授权的知识库，在超管开放的模型配置中选择产品默认值。共享资源由平台维护，产品绑定时记录具体授权和版本。
- **超管**从任一产品侧栏进入“平台管理”。“账号与角色”内分账号、角色两个页签；“供应商与模型”内分连接、聊天配置、多模态配置；“存储与服务”内分文件存储、服务设置。设备运维保留全平台资产视图。维护全平台模型或扩展与向某个产品发布该能力是两个独立操作。
- **个人中心**对接已有资料、安全、外观和个人模型页面；现有手机登录入口归入账号安全。个人模型已有授权在升级后继续有效，新增娱乐角色使用平台提供的模型即可开展创作。个人中心的设置与当前账号绑定。

## 菜单与权限如何配合

维护一份模块注册目录。菜单关联模块、产品范围、所需业务权限与排序。两个产品从同一目录生成默认树，平台页共用一份功能实现。五个预置角色提供默认授权，管理员可用角色范围调整可见性，前端无需为五种角色分别写导航。跨产品组合角色在当前产品内计算权限，保留接口级和数据归属校验。

“产品管理 → 菜单配置”默认打开当前产品。产品管理员只能调整本产品范围内已授权的菜单，可以改名、排序、分组、限定可见角色、预览及恢复本产品默认布局。平台管理入口由平台统一维护。产品管理员不能通过新增分组、猜 URL 或直接调用接口把平台菜单或另一产品的管理能力授予成员。菜单隐藏只调整入口展示，撤销功能访问应通过角色或产品授权。菜单修订与恢复按产品独立保存。

产品成员操作使用明确的产品范围，由服务端合并、撤销本产品的成员资格。在成员列表只返回当前产品成员及必要资料，避免把全平台账号搜索、禁用、删除、密码重置等能力下放给产品管理员。平台审计保留操作者、目标产品和变更内容。

## 迁移步骤

1. **先落权限边界。** 沿用了 `admin`、`member` 两个旧角色的 ID，分别对应超管、办公用户，并新增办公管理员、娱乐管理员、娱乐创作者三个角色模板。使用显式权限清单。对已有自定义角色、账号绑定和个人资源保持兼容，既有娱乐访问者保留原使用权，不自动升级为产品管理员。
2. **补产品管理接口。** 保留了显式全局授权的兼容入口，新增限定产品的成员管理、菜单编排、能力发布和模型默认值管理。读取、写入、批量操作及恢复均以登录账号权限和目标资源归属校验。产品未指定默认模型时沿用平台默认值。迁移保留已有娱乐覆盖，办公和娱乐均可独立配置。
3. **再接入菜单与页面。** 以现有模块标识和深链映射到新树。历史会话与我的设备沿用办公工作台能力。角色与账号、存储与服务等合并展示时保留原路由。产品成员、角色预览和受限模型选择按新流程补齐。新部署直接用默认树；已有菜单自定义保留标题、可见角色和已有排序，提供预览与按产品恢复新版布局。
4. **以角色验收。** 验证五种单角色和“办公管理员＋娱乐创作者”组合。逐一检查登录落点、一级分组、二级入口、直达路由、服务端写权限与数据范围。重点模拟办公管理员请求修改娱乐菜单、跨产品发布、改供应商密钥、授予管理员，以及删除双产品成员的办公资格。验证配置冲突、刷新、撤权、最后超管保护和两个产品的旧链接。
