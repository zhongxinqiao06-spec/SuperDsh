# 星桥娱乐创作准备阶段交付

对应[制作流程](starbridge-studio-workflow.md)阶段 B，承接阶段 A 的结构化工程。这次交付的是作品内可操作的准备流程：剧本确认、人物造型和声音候选、逐字段方案对比、静态分镜预演、代表镜头试做。旧 `apps/admin` 与办公执行内核保持独立。

## 页面与接口对应

以下前缀统一为 `/api/studio/projects/{id}`。页面根据账号、产品资格与作品归属操作，不使用角色名称判断权限。

| 页面入口               | 用户操作及持久结果                                                                 | 正式接口                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 八步导航、阶段检查     | 读取当前内容的确认状态；修改相关输入后显示待更新，保留已有媒体与剪辑               | `GET …/preparation`                                                                    |
| 剧本与场次             | 自动保存原文/改编模式，明确审阅后继续人物设定                                      | 既有工程保存、`POST …/stages/script/confirm`                                           |
| 角色与场景             | 人物/场景/道具卡片；素材表单移入抽屉，保留个人库引用与版本维护                     | 既有素材及工程接口                                                                     |
| 生成参考图、试听选音色 | 先展示模型、输入、参考数量与费用未知提示；确认才提交；结果只进入候选区             | `POST …/preparation/jobs?preview=true`、`POST …/preparation/jobs`                      |
| 候选与版本             | 预览、试听后明确采用；新版本替换本片对应引用，保留台词、其它素材、已采用视频和裁剪 | `POST …/preparation/adopt`                                                             |
| 设定检查               | 显示缺参考图、未试听的角色；定位打开对应卡片的候选；可选项须逐项略过并填写理由     | `POST …/stages/cast/confirm`                                                           |
| 导演方案对比           | 基线/当前/建议三列，对比动作、场景、时长、参考、台词、顺序和增删；冲突须明确覆盖   | `POST …/proposals`、`GET …/proposals/{proposal}`、`POST …/proposals/{proposal}/review` |
| 分镜设计               | 生成、比较和采用分镜图；复用公共媒体组件；检查后明确确认                           | 准备任务与采用接口、`POST …/stages/storyboard/confirm`                                 |
| 分镜预演               | 本地播放静态参考与已采用配音；字幕按起点显示；超长音频延长预演但不改工程           | 既有授权媒体接口；不提交渲染任务                                                       |
| 试做一镜               | 独立页面选择代表镜头，只提交所选镜头及其台词；比较、采用后确认，或记录理由跳过     | 既有制作预检/提交、候选保存、`POST …/stages/sample/confirm`                            |

确认状态不强制阻断用户查看其它步骤，不把浏览页面当作确认。已确认的阶段可直接进入下一步。导演助手从各步骤的同一入口打开，继续使用 DSH 工具调用，不另建 Agent 循环。旧逐镜审阅接口适配到同一个字段审阅服务。

## 数据与一致性

新增迁移 `fb720de395af_studio_preparation.py`，接续阶段 A。新增两张实际使用的表，不复制当前工程为第二套可写数据源。

| 表与字段                              | 类型、关联及约束                                            |
| ------------------------------------- | ----------------------------------------------------------- |
| `studio_stage_reviews.id`             | 字符串主键                                                  |
| `project_id` / `actor_id`             | 非空，分别外键关联作品与用户                                |
| `stage` / `decision`                  | 非空字符串；数据库限定四个准备阶段及 confirmed/skipped      |
| `project_revision` / `input_hash`     | 正整数修订及当前相关输入的摘要；确认针对内容而非任意修订号  |
| `reason` / `selections`               | 非空文本、JSONB；保留略过理由、具体检查项和所审看的试片镜头 |
| `created_at`                          | 带时区时间，数据库默认当前时间；按作品查询历史记录          |
| `studio_proposals.id` / `project_id`  | 主键、作品外键                                              |
| `base_revision`                       | 正整数，保存建议生成时的工程修订                            |
| `request_key` / `request_hash`        | 作品内请求号唯一，同号不同内容返回冲突                      |
| `base_document` / `proposed_document` | 非空 JSONB，只保存不可变比较基线与建议，不承载当前工程写入  |
| `state` / `resolution`                | pending/reviewed；可空 JSONB 保存所选字段和显式覆盖决定     |
| `created_at`                          | 带时区时间，数据库默认当前时间                              |

设定声音复用阶段 A 的 `studio_entity_versions.voice_configuration_id/revision/voice_parameters`，只读素材投影补充 `voiceBinding` 与 `voicePreviewJob`。换造型时保留已选声音；跨作品引用可复用声音配置，但不继承原作品试听链接。角色参考图仍指向正式公共文件与素材版本。

阶段确认、采用与审阅使用工程锁、修订检查和操作回执。字段合并以当前工程为基础，未选择的字段不写入；原文模式下导演提案和直接修改镜头均不能改写剧本或新增原文之外的台词。用户手工编辑仍由用户决定。

图片、试听复用现有持久媒体任务和唯一媒体调度器。图像提交只调用一次供应商，先保留回执，再下载校验真实图片。受理未知不自动重发；结果到达不自动采用。音色按后台模型配置校验，正式配音默认使用已采用角色的配置绑定；页面显式选择另一个模型时按该选择预检和执行。

## 使用与剩余范围

更新后端后，停止自己原先的开发后端，再在 `apps/web-admin/backend` 执行 `uv run python main.py`，由启动入口完成加法迁移；前端在 `apps/web-admin/fronted` 保持 `npm run dev`。这次未操作用户正在运行的开发服务或直接迁移用户业务库。

图片生成使用后台 `image.generate` 配置；当前参考图编辑适配 Ark，其它 OpenAI 兼容图片连接可做无参考生成。配音沿用现有百炼适配与后台 `speech.synthesize` 音色清单，不在前端写供应商地址、模型名或密钥。本轮未调用用户付费模型，不将受控传输测试宣称为真实模型效果验收。

个人库继续负责复用、上传与版本维护；独立于作品的个人库生成入口尚未交付。全批制作计划、依赖失效与取消/受理核对闭环属于 C，拖动时间线、自动排时、成片检查与完整导出规格属于 D。静态预演不能代替正式成片验收。
