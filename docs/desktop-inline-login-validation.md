# 桌面原位登录与主聊天

2026-10-08，Windows x64，中文目录 `D:\项目\SuperDsh`。此方案替换此前按平台账号切换 Home、重启应用的行为；原 RBAC 验收保留在[历史记录](platform-identity-validation.md)。

从原账户菜单输入平台地址、用户名或邮箱、密码；登录后自动连接本机。临时密码在同一窗口修改。本机始终使用原 Home、主侧栏和聊天区域；退出仅关闭平台连接。换账号若有任务则先确认停止，取消保留原账号和任务。其他电脑按需选择，不合并或下载其全部历史。

仅凭据、设备绑定和同步检查点按平台地址与稳定用户 ID 保存。同一本地历史同步为各账号的独立云端副本，不上传整个 Home、项目或模型密钥，不跨账号复用附件文件 ID。旧平台 Home 保留，旧数据必须通过原备份、空目标导入流程处理。

产品自行准备 Python 3.12、安装 Connector 依赖，再注册或核验并复用设备。连接进度区分 Python、依赖、注册、启动与同步；脱敏诊断写入产品日志。连接失败不阻塞本机使用。

## 设备连接与样式修复（同日）

实际桌面故障来自旧账号 Home 与当前本地 Home 使用不同 Chromium 加密密钥：平台账号已登录，但读取旧设备绑定失败，Connector 没有启动。只读日志与两个 `Local State` 的密钥差异确认了原因；列表里的同名离线项是服务器保留的独立设备记录。

修复后保留旧密文，恢复或创建按账号隔离的稳定安装记录。非敏感 `installation.json` 保存安装 ID 与设备 ID，重试或注册响应丢失仍可复用；恢复设备必须验证归属及封锁状态。设备令牌仅保存为密文并经私有 stdio 启动参数传入，临时 Connector 配置不再包含令牌。只有传输握手、服务端在线状态及原 Harness 运行时就绪才报告成功；断线和迟到轮询不会误报或干扰新连接。

设备、模型、权限和终端下拉共用桌面菜单，登录、文件及审批表单使用现有输入框、按钮和主题变量。默认显示本机与在线电脑，旧离线设备手动展开；同名设备以唯一短 ID、系统及最近连接区分，不按名称认领或自动删除。
